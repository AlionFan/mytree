# ASTRA-DESIGN-003：整图多题与免逐题校准

设计负责人：astra-lead。执行：codex-multiocr。日期：2026-11-14。状态：设计下发，未实现、未验收。

依据：codex-auth承接的新一轮用户明确要求——一张照片识别多道题；学生作答写在题干区域也要区分；取消孩子拍后逐题校准负担；探索能否找到题库原题。职责沿用[协作协议](README.md)，需求入口为[PRD](../PRD.md)。本文件由Astra独立认领；执行方认领业务、PRD、Schema及证据后实施。

## 1. 最新要求与旧决定的替代关系

**本轮默认主流程改为：拍照/上传 → 点击“识别并整理” → 按题展示可学习结果。** 不再要求先框选一道题，不再强制每题进入核对页并点击确认。清晰、完整、归属明确的题自动进入学习与合适的卡片记录。框选、查看原图和更正仍为可选恢复工具，不是孩子必须完成的手续。

替代 FR-001/002 及 ASTRA-DESIGN-002 B 中“多题必须框选”“每题核对后确认才能诊断”的默认交互，并更新 AC-02/03、AC-D2-U 中冲突场景。历史评审保留当时结论，不回写为本轮已通过。DESIGN-001 保留原作答、上下文消歧、禁止根据正确答案改写笔迹的原则继续有效，但候选选择不再成为整页继续学习的门槛。

原“未确认前不计进度”应准确替换为：**未有服务端有效来源及明确接收状态的内容不进入诊断；未核验的结果不记错因、错误次数、掌握或解锁。** 自动接收是识别流程决定，不是孩子手动确认，也不是数学正确性证明。学习记录可以自动整理，真正错题仅按现有核验规则形成；未核验题保存为待核验学习记录，不能贴“你做错了”。U1～U5、真实作答计分、账号隔离及读图gpt-6.1-sol不变。

## 2. 优先级、需求与执行范围

- P0：整图多题分割、题干/学生作答/教师批注归属、逐题状态与部分成功、自动学习登记；对应 FR-001/002/003/004/019、FR-018、NFR-002/003/005。
- P0：服务端来源绑定、自动接收记录、防重复与迟到响应、原作答可追溯；对应 FR-009/019/021、DEV-003。
- P1：原题检索官方能力核实与可插拔候选接口。不得以题库尚未接入阻塞前两项。若增加独立需求，执行方检查编号后以 FR-029“可追溯原题检索候选”登记规划/未接入，不写成已实现。

允许执行方认领：ai/agent/server/cards/reading_registry/readings及必要store、上传与学习前端、数学排版、对应测试、README、PRD/decisions、契约Schema/样例与证据。优先复用现有学习和核验逻辑，不改账号体系、不重做树或检验难度、不扩大到全文PDF后台批处理。Astra只维护本设计文件和后续独立评审。用户要求已明确，常规实现不需再次请用户许可；跨方已认领范围仍先交接。

## 3. 识别与逐题归属

1. 一次明确点击识别当前整张图片或当前PDF页，模型返回题目集合，不擅自仅挑一道。子问归属于同一大题，保留共享题干/图表，不能当独立无条件题拆走。双栏按版面阅读顺序展示，保留题号（可能缺失/重复）与独立稳定item_id，题号不能当唯一键。
2. 每题保留来源页、题目区域、题干文本、学生原样步骤、明确图表条件、疑点与归属依据。作答写在题干旁、题干中、上方或页边，不依靠“所在矩形”直接当印刷题干；允许题干区域与作答区域重叠。模型需区分 printed/handwritten/unknown，但不能仅凭印刷/手写推断角色：手抄题干仍可为题干，教师手写不等于学生作答。
3. 区域片段记录角色 problem/student_work/teacher_annotation/crossed_out/unknown；学生错误原样保留。无法明确属于哪题的笔迹单独记录为unassigned，不复制给每题，不拼接成臆造步骤。共享图表以明确引用关联各子问。
4. 印刷内容被覆盖、裁断、缺图或条件不完整时，禁止用“应该如此”补齐后自动判错。可提供部分转录及未核验讲解，但不能产生以缺失条件为依据的确定结论。
5. 只有同时满足完整题干、必要图形条件可用、作答归属明确、无未解决关键疑点、结果通过结构校验的题可自动接收。模型自报confidence不独立决定接收，不编造准确率阈值。无法确定学生有没有作答时不能默认为“未作答”以绕过歧义。
6. 初版每次最多整理12道独立大题，执行方须在服务端强制上限并展示限额。超限/截断必须明确“还有内容未处理”，保留原图并可选局部重试，禁止把前12题伪装整页全部成功。此为工程上限，不是模型能力声明；PDF仍按当前选定页，不自动遍历100页。

## 4. 自动学习与异常恢复

- 结果页直接显示“已整理 N 题，M 题暂未读清”，各题小卡保留题号、简短题干、状态和“开始学习”；第一道可用题可默认展开。无需孩子批量点确认、逐行纠错或补完整页。
- 逐题状态：ready（可自动整理）、needs_attention（缺条件/归属或关键字符不清）、unsupported（非支持范围）、failed（该题后续服务失败）。识别状态与诊断核验状态分开。整页模型输出无法解析时明确失败可重试，不把“零题”显示为识别成功。
- ready由服务端接收并自动调用既有学习流程：有原样作答按可核验范围分析；无作答是新题学习，不造错因。只整理内容不点亮知识点、不算答对检验。后续模型讲解不可用时，保留已识别题和可重试状态，不清空其它成功题。
- needs_attention默认“先跳过这题”，其余继续；可选“重拍这题”“查看原图”“我来改一下”，不弹出强制校准阻断整页。无题可用时简短说明具体原因，提供重拍/稍后处理，不能形成死循环。
- 自愿更正原题或步骤后创建新版本并重新诊断，关联被替代版本，停止把旧诊断作为当前题事实；不悄悄覆盖历史，也不追溯修改无关既有检验成绩。已有笔记保留。新旧题不得重复建卡或重复计数。
- 初次点击授权当前页识别及可用题整理；换文件/页本身不触发模型。一次识别请求不默认调用第二读图模型，不自动重复付费识别；仅重试失败题，不重做已成功题。逐题讲解沿既有供应商与计费调用，需有并发上限（建议2），结果页面可先显示已完成题。取消停止尚未开始的工作；在途返回按来源版本处理，不覆盖新页或再次计数。

## 5. 字段与兼容方案

当前`RecognizeOutput`、`reading_registry.confirm`和Agent `recognize→needs_confirmation`是单题强制确认契约，不能简单向严格Schema塞questions数组或伪造confirmed_reading_id。采用**新增批量辅助路由**，保留旧单题学习Agent操作的既有语义；这不新增第24个学习Agent操作。执行方在Schema/README先落以下字段的严格定义、长度/数组上限、错误与样例，再接客户端。

按执行方消息207对齐的路由：`POST /api/recognize/page`，输入image_data、request_id、client_generation与可选page_index；返回batch_id、source_revision、items、unassigned_fragments、overflow、warnings。服务端用当前邮箱会话决定profile，忽略/拒绝伪造目标档案。image_data不保存到普通日志或响应。

单题最小字段：

| 字段 | 含义 |
|---|---|
| item_id / reading_id | 服务端生成并绑定批次、档案与来源版本；不要信任模型自造ID |
| order / printed_number / parent_item_id | 阅读顺序、可空题号、可空父题引用 |
| region | 归一化[x,y,width,height]，与该页图绑定；校验0～1及边界 |
| problem / problem_latex / steps | 沿用已支持字段长度；完整题干为权威，latex片段不得补造缺失条件 |
| diagram_description / fragments | 图表条件及角色片段，可记录重叠区域；不传标准答案当学生步骤 |
| readiness / attention_reasons | 服务端复核后的逐题状态与具体阻碍，不只给一个confidence数字 |
| provenance | source_kind=photo、page_index、转录版本；题库候选单独记录，不覆盖照片转录 |

`POST /api/study/reading`接受reading_id及request_id；来源版本由reading_id不可变记录关联，不要求客户端再传题文。客户端在识别后以受限并发自动调用ready子集，不需额外确认按钮。服务端再次读取已登记内容、batch/source_revision和接收策略，不能信任客户端auto_ready=true、steps或“已确认”。每题记录acceptance=auto/manual、policy_version与source_revision；复用study核心前先生成真实服务器接收凭据，不借strict=False绕过保护。每次响应返回该题study状态、card/context引用、核验等级与错误；页面汇总为部分成功，重试仅针对失败题。

字段命名允许使用消息207的auto_ready与association_status：auto_ready必须由服务端校验得出，association_status与缺失原因保留，前端不能把布尔值当数学正确性；与本设计readiness/attention_reasons做唯一映射，不维护两套互相矛盾状态。旧确认接口可继续作为自愿更正路径。此对齐替代初稿两条batch路由建议，不需同时维护额外别名。

同档案+批次+item+来源版本建立业务幂等键；不同request_id的同一题重试也不能重复记账。旧读取凭据、跨档案item、过期/错误版本拒绝（404隔离，409过期/冲突）；无鉴权401，整体无效输入400，超体积413，整体模型失败沿既有502/503/504，服务端限流429。识别页合法且有部分待处理时返回200+逐题状态；学习reading路由按本题返回实际状态码，页面聚合部分成功，不伪装全部成功。服务重启后已持久化学习结果不得重记；识别缓存若过期则明确恢复/重新识别，不无限转圈。

旧单题路由及旧客户端继续可用，单题批量结果也走同一新体验。不得自动导入匿名档案。新增auxiliary Schema按现有契约验证器规则补正反例；与仍在工作的契约维护方有占用时先发具体字段提案，不绕过claim。

## 6. 原题检索边界

当前没有已核验的官方题库API、授权与凭据，**不能宣称已像某搜题产品那样查到原题**。由codex-multiocr核实官方文档、可申请入口、许可/费用和图像或文本查询能力，记录来源与日期；不抓取需要登录的题库、不绕过鉴权、不把搜索网页片段当完整可靠题源。

首版检索适配器可返回not_configured/no_match/candidates/error；未接入时主识别流程照常。候选必须记录provider、source_url或provider_item_id、检索时间、匹配依据与条件差异。题干语义、所有数值/符号/子问、必要图形条件一致才可标“找到匹配题目”；不一致显示“相似题”，不自动替换原题。来源只允许模型重构时标“AI整理文本，非题库原题”。任何候选的答案都不能反推、修正或补造学生笔迹，也不能作为程序核验结果。

缺失条件无法核对一致的题，即使搜到相似题仍保持待处理；不得以检索成功自动跨过归属和核验要求。真正接入外部题库前遵守其授权，并明确传输的数据范围；未有必要时不向题库发送学生整页手写或账号资料。
