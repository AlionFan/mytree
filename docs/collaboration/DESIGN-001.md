# DESIGN-001 · 模糊字符结合上下文消歧

状态：**已下发，待字段提案确认、实现与 Claude 验收**。排在 Codex 当前浏览器验收收尾之后，收尾继续。

## 问题与目标

学生书写会涂改，系统应根据题干和已识别的同题学生书写判断模糊位置，而不是遇到一个不清字符就停住、随机选读法或要求整行重输。例如候选是 2 / 7，学生后文列出的整数解是 −1、0、1、2，可支持读成 ≤2。

必须保留学生的真实错误：不能用标准答案或“数学上应该解成 2”来选择 2，否则真写成 7 的错误会被隐藏。证据案例来自 `mytree/eval/results/real-155000.json`；它说明问题类型，不提供稳定准确率。

## Claude 确定的修改要求

1. 依据只来自题干印刷内容及学生同题其他书写，包括后文、结论、整数解 / 解集、同一数字或式子的重复书写、下一行引用。
2. 禁止使用标准答案、程序判对错结果或预期正确解法消歧。提示词和测试都必须保护这一边界。
3. 每个模糊位置返回 2–3 个候选及依据，说明引用学生写的哪一处，不能只返回单值。
4. 程序先仅核对有限的一致性：不等式结论与学生列的整数解 / 解集；等式链上下行重复的项；最后答案行与前一步的一致性。不做通用推理判定。
5. 仅一个候选一致时采用，标 `inferred=true` 并附依据；多个或没有候选一致、学生前后矛盾时不猜，列候选供一键选择。
6. 显示“我读作……，依据：你后面写的……”，可一键改为其他候选，改后重新诊断。确认前不诊断、不计错题的既有规则保留。
7. 划掉内容记为 `[划掉:…]`，不当作学生作答；重写内容才是作答。无法确定划掉还是笔画时按模糊候选处理。
8. 使用 `gpt-6.1-sol` 读图，不自动切换。

## 接口与修改范围

允许范围：`mytree/app/ai.py` 识别部分、识别结果结构、`mytree/web` 核对界面及相关测试。

Claude 初始字段要求：`inferred`（布尔）、`reading_evidence`（字符串）、`alternatives`（候选列表），原字段保留，旧客户端可忽略新字段。**这是待 Codex 回复、Claude 确认的接口提案，不把它写成已上线 HTTP 契约。** 多个模糊位置的具体结构由该对齐过程明确。
