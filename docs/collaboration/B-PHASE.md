**目标：** 把「拍题 → 错题卡 → 主动复习提醒 → 检验解锁知识卡 → 孩子拖拽整理知识树」这条线在本机真正跑通，每一段都能由我独立复现。

## 1. C2：本阶段的提醒终端（已决定）

**要求：孩子没有打开学习页面时，也能收到提醒。**

**选定方案：macOS 本机系统通知，由 launchd 用户代理定时触发。**

依据（我只读核对过，不是推测）：
- 本机 macOS 27.2.1，`osascript` 与 `launchctl` 都在；`display notification` 实测可发出（我发过一条测试）。
- `~/Library/LaunchAgents` 存在且当前用户可写。
- 本机没有 Android 模拟器程序、没有系统镜像、没有已创建的 AVD、没有已连接的安卓设备（SDK 里只有 `android-35` 平台和构建工具，能编译，不能运行）；现有 `android/` 原型也不调用服务，没有通知权限与后台任务。**所以 Android 不能作为本阶段能验证的终端。**
- 网页 Service Worker 通知依赖浏览器权限、HTTPS 和浏览器进程在后台存活，本阶段无法稳定验证，**不选**。

做法：
1. 一个独立小程序 `mytree/reminder/mytree_reminder.py`（仅标准库）：每次运行时调用 `GET /api/review/today?student=…`（见任务 T3），有待办就发一条系统通知，没有就静默退出。
2. launchd 用户代理 `cn.joybeat.mytree.reminder`，每 15 分钟运行一次。**只做仓库内的安装脚本和 plist 模板，由用户自己执行安装命令，不由 Codex 或我自动 `launchctl load`。** 这是写入用户登录项，属于需要用户确认的系统设置变更。
3. 提醒内容遵守 PRODUCT-001 第 4 节：每天最多提醒一次、一次最多 3 项、只在孩子设定的空闲时段内、孩子可以「今天不看」、**不使用催促或恐吓措辞**。
4. 提醒状态（今天已提醒、今天不看）记在服务端，**不记在提醒程序里**，这样换终端也一致。

**C2 的验收口径（我自己执行）：** 关闭所有浏览器窗口，把一条复习任务的到期时间设为现在，手动运行一次提醒程序，**必须看到系统通知**；再运行一次，**不得重复弹**；设为「今天不看」后再运行，**不得弹**。这三条都过，才能在文档里写「C2 在 macOS 本机终端已验证」。**不能写成「产品已具备主动提醒」**，因为它只在这台电脑上、需要用户安装代理。
**Android / 硬件 / 网页后台通知：** 契约不变，本阶段不做，文档写「待后续阶段」。

## 3. 任务单

### T1 · 数据层与服务端模型

**目的：** 为卡片、检验、树、成长提供可靠存储，并加上 U4 需要的提示访问记录。
**文件范围：** `mytree/app/profile.py`（扩展）、新增 `mytree/app/store.py`（如需要）、`mytree/tests/test_store.py`。
**做什么：**
1. 现有档案是单个 JSON 文件整体读写。保留，但在其上定义清晰的集合：`wrong_cards`、`knowledge_cards`、`quizzes`、`quiz_answers`、`hint_views`、`tree`、`growth_events`、`reminders`。
2. 每次写入仍然原子、加锁，写失败返回 `STORAGE_FAILED`，**不得显示已保存**。
3. 新增**提示访问记录**：孩子展开第 N 级提示时，客户端调用一个服务端接口（见 T2），服务端记录 `(diagnosis_id, level, at)`。`quiz.answer` 返回的 `max_hint_level` 取自这里，**不取自客户端自报**。
4. 旧档案向后兼容：缺新集合时自动补空，不丢旧数据。
**验收（我执行）：**
- `python3 -m unittest` 全部通过，通过数报给我。
- 手工构造一份旧格式档案，启动后读取不报错，旧的错因计数、点亮、复习仍在。
- 在写盘前强制抛 `OSError`，接口返回 `STORAGE_FAILED`，并且读回确认没有半截数据。

### T2 · 错题卡与提示访问

**目的：** C1。拍题确认后产生可持久、可列出、可补充笔记的错题卡。
**文件范围：** `mytree/app/server.py`（新路由）、`mytree/app/profile.py`、新增 `mytree/app/cards.py`、`mytree/tests/test_cards.py`。
**接口（按 Schema 的操作名对应）：**
- `study` 确认后写入错题卡，`effects` 含 `create_wrong_card`；**同一 `request_id` 重放返回首次结果，不重复建卡。**
- `card.list`：列出错题卡与知识卡，可按类型过滤。
- `card.edit`：只允许改孩子笔记与知识卡标题；**AI 生成的诊断部分只读**，写入被拒绝。
- 新增 `POST /api/hint/view`：记录提示访问。
**规则：**
- 只有已确认的题才建卡；`not_attempted` 的纯题干学习建卡时标「学习卡」并不计入错题统计。
- 卡片必须指向它的诊断与知识点。
**验收：**
- 用 `tests/test_ai.py` 的假上游走一遍：识别 → 确认 → 诊断，列表里出现 1 张错题卡；同一 `request_id` 再来一次，仍是 1 张。
- `card.edit` 试图改诊断文字 → 被拒绝（具体错误码），改笔记 → 成功并保存，刷新后仍在。
- 展开提示 1、2 后调用 hint/view，读回 `max_hint_level=2`。

### T3 · 复习待办与提醒状态（C2 的服务端部分）

**目的：** 终端能拉到「现在该提醒什么」，并且提醒不会重复、孩子能说「今天不看」。
**文件范围：** `mytree/app/server.py`、`mytree/app/schedule.py`、新增 `mytree/app/review.py`、`mytree/tests/test_review.py`。
**接口：**
- `GET /api/review/today?student=…`（对应 `review.today`）：返回今日待办，**最多 3 项**，每项含具体小任务（一道题或一个回忆问题）与理由，并含 `reminder_allowed`（是否在空闲时段内、今天是否已提醒或已跳过）与 `reminder_key`。
- `POST /api/review/ack`：终端提醒已发出，记录当天已提醒；同一 `reminder_key` 重复调用幂等。
- `POST /api/review/snooze`：孩子「今天不看」，当天不再提醒。
- `review.complete`：复习完成，更新事实；**只有 `verified` 的答对才算有效复习**。
**规则：**
- 提醒节奏：每天最多提醒 1 次；孩子连续 3 天「今天不看」后，提醒频率降为隔天（降低，不增加）。
- 时间一律按 Asia/Shanghai；空闲时段沿用 `/plan` 的设置。
- 不使用催促措辞；接口返回的 `message` 字段由服务端生成并固定模板，不由模型临场写。
**验收：**
- 把一个复习任务的到期时间设为过去 → `today` 返回该项且 `reminder_allowed=true`；`ack` 之后再查 → `reminder_allowed=false`。
- 构造 4 个到期任务 → `today` 只返回 3 个，另 1 个次日出现。
- 空闲时段外查询 → `reminder_allowed=false`。
- `snooze` 之后当天 `reminder_allowed=false`，次日恢复。

### T4 · 检验与解锁知识卡（C3）

**目的：** 孩子只有通过检验才能得到知识卡，没有其他途径。
**文件范围：** `mytree/app/server.py`、`mytree/app/practice.py`、`mytree/app/junior_practice.py`、新增 `mytree/app/quiz.py`、`mytree/tests/test_quiz.py`。
**接口：** `quiz.start`、`quiz.answer`、`card.unlock`，字段严格按 `docs/architecture/agent-contract.schema.json`。
**规则（PRODUCT-002 第 3 节，逐条实现）：**
- 一组 3 题，其中至少 1 道迁移题；题目与答案由服务端保存，**客户端永远拿不到答案**。
- `quiz.answer` 只收 `quiz_id`、`exercise_id`、`answer`；对错由服务端批改，响应带 `max_hint_level`（来自 T1 的提示访问记录）。
- `card.unlock` 只收 `quiz_id`，服务端判断 U1～U5，响应带逐条结果；**不满足不解锁**，并给出原因。
- 一个知识点只解锁一次；再答对只计复习事实，不产生新卡。
- 难度档位是程序标注的题目属性；本阶段至少实现「全对且没用提示升档、≤1 题降档并给支架」的服务端选择逻辑。
**验收：**
- 全对且没看第 3 级提示 → 解锁，得到知识卡，来源指向错题卡。
- 全对但看过第 3 级提示 → **不解锁**，原因为 U4。
- 答对 1 题 → 不解锁。
- 答对 2 题但没有迁移题答对 → 不解锁，原因为 U2。
- 构造含 `ai_review` 的题 → 不计入 U3。
- 对同一知识点再来一组全对 → `reused_existing=true`，知识卡仍只有 1 张。
- 客户端在请求里夹带 `correct:true` 或 `score` → 被拒绝（Schema 层）。
- 重复提交同一题正确答案 → 只计一次。

### T5 · 知识树与成长

**目的：** C4。孩子能编排自己的树，位置和关系持久化；成长分按去重事件累计。
**文件范围：** `mytree/app/server.py`、新增 `mytree/app/tree.py`、`mytree/app/growth.py`、`mytree/tests/test_tree.py`、`mytree/tests/test_growth.py`。
**接口：** `tree.get`、`tree.move`（含 `undo_token`、`expected_revision`、`method` 为 `drag` / `keyboard` / `menu`）、`growth.get`。排行榜 `leaderboard.get` 本阶段**只返回自己的成长与说明「小组未开启」**，不做多用户。
**规则（PRODUCT-002 第 5 节、8.1 节）：**
- 位置自由；合理性只评估知识关系，对照 `knowledge.py` 的前置关系；目录没有的关系不计分不判错；与目录相反提示一次。
- 成长分 = 规模 + 茂盛度 + 关联；按 `knowledge_id` 与（`from`,`to`）关系对去重；**移除卡片、撤销连线不减历史成长分**；删了再建不重复得分。
- `expected_revision` 不匹配 → 返回冲突，不覆盖（防止两个标签页互相覆盖）。
- 撤销只撤最近一次。
**验收：**
- 把卡片放入树，刷新后位置还在；键盘方式（不拖拽）能完成同样的移动。
- 连一条与目录一致的关系 → 成长分关联 +2；删除后再建 → 总分不变。
- 连一条目录里相反的关系 → 提示，不加分，也不扣分。
- 带过期的 `expected_revision` → 冲突错误，树不变。
- 成长分三部分之和等于总分（由测试断言）。
- **成长分任何情况下不下降**（写一个随机操作序列的测试，断言总分单调不减）。

## 5. 通用约束（违反则该项返工）

- 密钥只在服务端环境变量，不进代码、文档、日志、截图、共享消息。
- 读图模型仍是 `gpt-6.1-sol`，不自动换；**不得为跑测试发真实照片**，测试一律用假上游或合成数据。
- 不得把设计样例当真实返回，不得把「接口存在」当功能完成。
- 不用「掌握」「已解耦」「闭环已打通」「保证提分」之类说法；掌握度只有三档。
