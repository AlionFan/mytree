## 1. 决定摘要

1. 知识卡是**解锁**的，不是**发放**的。解锁依据是可核验的答题证据，孩子自述「懂了」不算。
2. 难度要「够得着」。答错不扣分、树不会枯萎，只会降一档并给支架。
3. 树的成长分只计**可核验**的证据；规模、茂盛度、关联三部分，公式见第 5 节。
4. 排行榜按**小组、昵称、成长**，不展示能力评价和错题。真实多用户计分要等账号与监护人授权（FR-018），本阶段只定契约。
5. 随机酬赏本阶段**不做**。
6. 投入要包含孩子的笔记和自己连的关系，并且要让下一次体验变好，不只是「再拍一题」。

## 2. 习惯循环与边界

| 环节 | 本产品里是什么 | 明确不做 |
|---|---|---|
| 触发 | 外部：`review.today` 待办，由客户端提醒，每天最多 3 项，只在孩子设定的空闲时段。内部：想弄明白这题为什么错。 | 不催促，不用「同伴已经超过你」之类的话刺激 |
| 行动 | 一组 3 题的检验，难度适中，随时可以停 | 不设倒计时，不比速度 |
| 酬赏 | 解锁知识卡、树长叶、成长分上升 | 失败不扣分，树不枯萎，不掉叶 |
| 投入 | 知识卡笔记、自己连的关系和理由、偏好设置 | 不做「连续打卡中断就清零」，不锁定数据 |

说明：用户把「首次拍错题」定为触发。我保留这个起点，同时指出：能让习惯**重复**发生的是 `review.today` 这个外部触发，所以它是习惯循环的关键，C2 的实机验证因此重要。

投入的作用要改善下一次体验（这是 Hooked 作者的原意，见消息 48）。本产品里的落点：`recommend.next` 的理由里引用孩子写过的笔记，例如「你在笔记里写过括号前是负号容易忘，今天这组重点练它」。**这是设计意图，实现前不得宣称已有。**

## 3. 知识卡解锁：需要什么证据

**解锁条件（全部满足才解锁；任何一条不满足，只记练习事实，不发卡）：**

| 编号 | 条件 | 说明 |
|---|---|---|
| U1 | 对应知识点的**一组检验**中答对至少 **2 题**（共 3 题） | 由服务端批改，沿用 FR-008，答案和判定依据不下发到客户端 |
| U2 | 答对的至少 2 题中，**至少 1 题是有效迁移题** | 迁移题：同一知识点、换了数字或情境；不得与原错题只差一个数。组里含迁移题但该题做错，不算达标（2026-11-14 按 codex-prd 消息 52 收紧） |
| U3 | 所有题目的核验等级为 `verified` | `ai_review` 的题只算练习，不计入解锁 |
| U4 | 答对的题**没有使用第 3 级提示**（完整解法） | 看了完整解法再答对，不算 |
| U5 | 题目来自服务端保存的组，不是客户端自己提交的 | 防止伪造 |

**不解锁：** 只看提示、点「懂了」、浏览题目、答案是否正确无法程序核验的开放题。
**知识卡与错题卡的来源关系不变：** 一张知识卡至少引用一张错题卡（FR-021 / PRODUCT-001 第 3 节）。
**一个知识点只解锁一次知识卡。** 之后再答对只算复习事实与成长分，不产生新卡。孩子对卡的编辑不影响解锁状态。

**同一组、重复提交：**
- 同一道题重复提交正确答案，只计一次（沿用现有幂等）。
- 同一组不能重复用于解锁。已解锁的知识点再出新的一组，只用于巩固。
- 解锁以服务端记录为准，客户端不能自报。

## 4. 难度调节（适度挑战）

目标：孩子大约在 **60%～80%** 的题上能答对。这是教学经验里常说的「够得着」区间，**我没有本产品的数据，这个区间是起点，不是结论**。

| 情形 | 调整 |
|---|---|
| 一组 3 题全对，且没用提示 | 下一组升一档，或推荐相邻知识点（受 PRODUCT-001 第 6 节约束：只有 stable 才超前） |
| 一组答对 2 题 | 保持 |
| 一组答对 ≤ 1 题 | 下一组**降一档**，并先给一个例题或支架提示 |
| 连续两组答对 ≤ 1 题 | 停止出新题，回到该知识点的知识讲解，提示「今天先看懂这一块，明天再练」，**不扣任何东西** |

规则：
- 难度档位是 **程序标注的题目属性**（例如步骤数、是否含分式、是否含参数），不是模型临时说「这题偏难」。
- 孩子可以随时退出，退出不影响任何已有记录。
- 不用倒计时，不显示「你比 X% 的同学慢」。
- 不因为答错而扣成长分、不降树、不删卡。

## 5. 树的成长与排行

### 5.1 成长分（只计可核验证据）

成长分由三部分相加，每部分都能追溯到服务端记录：

| 部分 | 含义 | 起点算法 |
|---|---|---|
| **规模** S | 已解锁的知识卡数量 | 每张知识卡 +10 |
| **茂盛度** L | 复习的持续与深度 | 每个知识点间隔 ≥ 3 天的有效复习（答对且 `verified`）每次 +3，同一知识点最多计 3 次 |
| **关联** R | 孩子连的关系是否合理 | 每条被评估为「合理」的连线 +2，见 5.2，上限 20 条 |

总成长分 = S + L + R。**没有倍数、没有连续打卡奖励、没有衰减。**

### 5.2 关联评估（回答「自由编排」与「放对位置」的冲突）

决定：**评估知识关系，不评估像素位置。**
- 孩子仍然可以自由摆放卡片、自建分组。
- 一条连线（A 是 B 的前置、A 与 B 相关）的合理性，对照**课标目录的前置关系**（现有目录 31 个前置关系）判断：与目录一致 → 合理；目录里没有但孩子写了**理由**，标记「孩子自己的联系」，**不计分也不判错**，进入人工或教师复核池；与目录相反 → 提示一次，不计分，不扣分。
- 孩子的**理由文字**可以被模型阅读并给出评语，但**评语不计分**，避免用语言模型的主观评分决定排名。
- 评估只依赖知识点编号，不依赖卡片在画布上的位置。

### 5.3 排行榜

| 项 | 决定 |
|---|---|
| 比较什么 | 成长分，以及它的三部分明细。不比正确率、不比速度、不比错题数 |
| 同组范围 | 同一**小组**（班级或家庭自建的小组，由监护人创建并授权）。不做全站公开榜 |
| 显示什么 | 昵称、成长分、树的缩略图。不显示真名、学校、错题、错因、画像推断 |
| 排名方式 | 每周一个周期，周期内成长分增量排名；另可看总成长分。周期榜让新加入的孩子有机会 |
| 退出 | 孩子或监护人可随时退出，退出后不再显示 |
| 防重复刷 | 一个知识点解锁一次；茂盛度每点最多 3 次；关联上限 20 条；同一道题只计一次 |
| 防伪造 | 所有计分以服务端记录为准，客户端不提交分数 |
| 失败的呈现 | 只显示自己的变化，不显示「你掉到第几名」类的负面提示 |

**阶段边界：** 真实多用户排行需要账号、监护人授权、昵称审核与数据隔离，属 FR-018，**本阶段只定契约和示例，不接入真实排行，也不把本机匿名档案当作多用户系统。** 排行榜上线前，需要评估对未成年人的比较压力，需用户和监护人确认。

## 6. 随机酬赏

本阶段**不做**。理由：
1. 没有真实用户数据，无法判断什么酬赏有效，也无法评估对未成年人的影响。
2. 随机奖励容易形成难以停下的使用模式，对未成年人风险高于收益。
3. 若以后探索，只允许：解锁时随机出现的**装饰性**内容（例如叶子的样式），**不影响成长分、排名和任何学习内容**；不使用「抽奖」「再来一次」之类的措辞。该条需要用户另行确认。

## 8.1 实现契约边界（回复 codex-prd 消息 52，2026-11-14）

**提示记录（U4 的前提）：**
- `quiz.answer` 的输入只含 `quiz_id`、`exercise_id`、`answer`，不含客户端自报的对错、分数、提示级别；输出带服务端记录的 `max_hint_level`。已核对 Schema，一致。
- 提示级别必须由**服务端在孩子展开提示时记录**，不由客户端在答题时上报。
- **当前代码没有这条记录**：三级提示是前端逐级展开，服务端不知道孩子看了第几级。因此 B 阶段必须新增「记录提示访问」的服务端行为，作为 U4 的前置条件，并写入 B 阶段验收。
- 在此之前 **U4 无法被强制，文档不得宣称 U4 已生效**；契约里可以保留该字段，但标「待 B 阶段实现」。

**历史成长分与布局分离：**
- 规模分和关联分按**去重的历史事件**累计：首次解锁某知识点计一次；首次出现某条合格关系计一次。
- 事件键用 `knowledge_id` 与（`from_knowledge_id`, `to_knowledge_id`）关系对，**不用卡片编号或连线编号**。否则「删了再建」会变成新卡新分，可被刷出来。
- 孩子移除卡片、撤销或删除连线，**不减少历史成长分**。树上不再显示该卡，但成长分明细保留「已解锁」事实。排行榜缩略图可以不显示它。
- 重新添加同一知识点的卡或同一条关系，不重复得分。
- 茂盛度按（知识点，间隔 ≥ 3 天的有效复习）去重，已有每点最多 3 次的上限。
