## 1. 定位（一句话）

**不是答疑助手，是陪孩子把错题变成知识、再把知识长成自己的知识树的学习 Agent。**

要解决的事：孩子在学校学习和考试后会整理错题，但很少主动复习，也很少分析题背后的知识点和自己的卡点。产品替孩子整理、分析、迁移，然后**主动**把值得看的东西推给孩子，让孩子自己动手整理成知识树。

和通用 AI 对话助手的区别，只承认这三点，路演和文案只能写这三点：
1. **会推。** 孩子不开口，它也会在合适的时间带着具体内容来找孩子。
2. **记得。** 它越用越了解这个孩子，画像随每次交互更新，并且能说出依据。
3. **孩子是作者。** 知识树由孩子亲手整理，不是系统生成后展示。

不得写：把产品称为「AI 老师」、承诺提分效果、宣称孩子已经彻底掌握、宣称比通用助手更准。我们没有证据。

## 2. 核心闭环

```text
拍题 → 识别核对 → 错题卡（AI 整理）
        ↑                              ↓
   画像更新 ← 复习与练习 ← 主动复习推送
        ↓                              ↓
   迁移与进阶推荐            复习完成 → 知识卡（孩子整理）
                                          ↓
                               拖入知识树，孩子自己编排
```

闭环成立的最低条件，缺任一条都不能说「闭环已打通」：
- C1 拍题后系统自动生成错题卡。
- C2 系统在到期时**主动**提示孩子复习，不靠孩子自己打开。**满足条件：** 孩子没有打开学习页面时，终端也能拉取待办并发出提醒。仅在孩子打开页面后才显示的红点、列表，只算「应用内待办展示」，**不算** C2 满足。
- C3 孩子**通过检验后解锁**对应知识点的知识卡（条件见 PRODUCT-002 第 3 节；原写法「完成复习后得到」已被覆盖）。
- C4 孩子能把知识卡拖到树上，位置被保存，刷新后还在。
- C5 复习和练习的结果会改变画像，画像会改变下一次推荐。

当前现状：C1 部分有（诊断卡），C2、C3、C4、C5 都没有。**只读知识树加被动复习列表，不算新闭环完成。**

## 3. 两类卡片（命名已定）

| | **错题卡** | **知识卡** |
|---|---|---|
| 谁生成 | AI 整理，来自一道具体的题 | 孩子复习完某个知识点后形成，内容来自复习过的错题卡 |
| 时机 | 拍题确认后 | 一个知识点的一组复习或练习完成后 |
| 内容 | 题、学生作答、卡点、错因、三级提示、关联知识点 | 知识点名称、孩子自己的话（可选）、关键规则、易错点、代表题（引用错题卡） |
| 谁能编辑 | 学生可补充「我当时怎么想的」；AI 部分只读 | 孩子可改标题、补笔记；规则部分标明来源 |
| 在树上 | 不上树 | **上树，由孩子拖动** |
| 核验等级 | 沿用 verified / ai_review / unavailable | 规则部分带等级；孩子的笔记标「孩子笔记」，不带等级 |

规则：
- 一个知识点可以有多张错题卡，复习完只形成**一张**知识卡，不重复生成。
- 知识卡必须有来源，指向至少一张错题卡，防止凭空生成。
- 孩子删除知识卡不删除错题卡与历史记录；删除知识卡只是从树上拿掉并标已移除。
- AI 不得替孩子决定卡片放在树上哪里。

## 4. 主动复习

**推什么：** 到期复习的知识点，附一个具体的小任务（一道题或一个回忆问题），而不是「该复习了」。
**什么时候推：** 沿用每周空闲时段与 1 / 3 / 7 天阶段。只在孩子自己设置的空闲时段内推。
**推送边界（决定）：**
- 推送是 **Agent 产出一个复习待办，由客户端选择如何提醒**。Agent 不直接调用系统通知、不发短信、不对接日历。
- 网页：打开时显示「今日复习」并给出红点。这是**应用内待办展示，不满足 C2**。网页要满足 C2，需要浏览器在页面关闭后仍能提醒（例如系统通知权限加后台任务），这依赖通知权限与账号，本阶段不做，因此**网页端在本阶段不宣称 C2 已满足**。
- C2 的第一个可验证的终端是 Android 或硬件：由客户端在后台定时调用 `review.today`，到期弹出提醒。未实机验证前，文档只能写「契约已定义」，不能写「已主动提醒」。
- Android / 硬件：以后由客户端拉取待办并提醒，不是 Agent 推过去。
- 每天最多提示一次，每次不超过 3 项，孩子可以「今天不看」，当天不再提示。孩子连续忽略则降低频率，不增加。
- 不用「再不复习就会忘」之类的话催促。语气沿用 H4。

**为什么把推送放在客户端：** 这保持 Agent 独立可复用，也避免我们在没有账号体系的阶段去碰通知和未成年人联系方式。

## 5. 持续画像

画像分三层，**必须区分，界面和接口都不得混写**：

| 层 | 含义 | 例子 | 能否由孩子改 |
|---|---|---|---|
| **事实** | 系统记录到的行为 | 做过 12 次练习；某错因出现 5 次；上次复习是周三 | 否 |
| **推断** | 系统由事实推出的判断，带依据和置信说明 | 「平方差公式可能没掌握：连续两次在同一步出错」 | 孩子可以反驳，反驳被记录，推断降级 |
| **偏好与目标** | 孩子或家长告诉我们的 | 空闲时段；想先巩固还是想超前 | 是 |

规则：
- 每条推断必须能指出引用了哪些事实。指不出依据的推断不得展示。
- 推断不是评价。不写「基础差」「粗心」「不聪明」。
- 掌握度不是「点亮」。点亮表示做对过一次，掌握度需要多次、间隔后的证据。本阶段定义三档：`未接触`、`在巩固`、`较稳定`。升到「较稳定」至少需要：同一知识点间隔 ≥ 3 天的两次独立做对，且最近一次无提示。降档同理。
- 孩子的主观「懂了」只记事实，不改掌握度。
- 家长看板展示事实与推断，推断标「系统推断」。

## 6. 迁移与进阶推荐

**迁移**：从一道错题关联到同一知识点的变式、相邻知识点、前置知识点。
**进阶（超前）**：孩子某知识点掌握度为「较稳定」，且其后继知识点尚未接触时，才可推荐后继内容。

决定：
- 推荐只能基于第 5 节的事实和掌握度。没有证据不推荐超前内容。
- 每条推荐必须写明理由：「你已经稳定掌握了提公因式，可以试试和它相邻的完全平方公式」。
- 推荐题必须来自可核验的练习（沿用 FR-008），不得由模型临场编造一道无法校验的题。无法核验的只能作为「了解」内容，标 `ai_review`。
- 超前内容每周最多 1 个知识点，孩子可以拒绝，拒绝记为偏好，不再短期重复。
- 知识点之间的前置与后继，依据现有知识目录的 `pre` 关系；该关系不完整的部分不推荐。

## 7. 孩子拖拽的知识树

- 树是**孩子的作品**。节点是知识卡，位置、层级、分组、连线由孩子决定。
- 系统提供**参考结构**：现有课标目录（9 章 37 节点）作为灰色骨架，帮助孩子找位置。孩子可以放进骨架，也可以自建分组。
- 系统给**提示，不强制**：把卡放到与课标位置不一致的地方，只提示「课标里它在 X 章，要不要看看」，不阻止。
- 保存：每次拖动保存位置与父子关系，刷新后保持。可撤销最近一次。
- 可访问性：必须有**非拖拽的操作方式**（选中卡片，用菜单或键盘选择放入哪里），触屏和键盘都能完成。
- 家长可看，不可改。

## 12. 用户已确认与仍需确认的事

**用户已确认（2026-11-14）：** 本文全部决定没有异议。其中两个数字按「起点」使用：
- 「较稳定」判据：同一知识点间隔 ≥ 3 天的两次独立做对，且最近一次无提示。
