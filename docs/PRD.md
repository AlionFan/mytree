## 1. 产品目标与边界

**小树同学是帮助孩子整理错题、主动复习并亲手建构知识树的学习 Agent。** 孩子在学校学习和考试后积累了错题，却缺少主动复习、分析知识点和发现自己卡点的动力。产品用 AI 将错题整理成可探索的内容，在合适时间带着具体任务提醒孩子复习；孩子通过检验解锁知识卡片，亲手编排自己的树。学生是主要使用者，家长提供辅助；当前已有部署的邮箱账号体验版；历史双方邮箱只读关联曾发布；现按用户新要求改为同账号独立家长密码，当前实现/验收状态见FR-033；监护身份核验、数据导出/删除等正式使用前置仍待接入。

核心价值：主动带来复习内容；持续了解孩子并能说明画像的依据；让孩子成为知识树的作者。对话用于围绕卡点探索，产品持续输出错题卡、复习待办、知识卡、个人知识树和有证据的下一步建议。具体方向由 Claude 的 [PRODUCT-001](collaboration/PRODUCT-001.md) 决定，覆盖早期以一次诊断为中心的范围。

产品目标是初中数学。现有经过闭环验证的起点为因式分解、分式化简；代码中扩展的方程、函数、几何、统计、概率等能力，需要分别完成前后端联调和验收后才能宣称支持。知识目录数量不代表教学与判题覆盖率。

核心成果：题目与原样作答 → AI 整理的错题卡 → 带具体小任务的复习待办 → 适合当前水平的练习 → 答对检验 / 迁移题后获得知识卡 → 孩子亲手编排并养大知识树。树的成长与多用户排行提供成就反馈，交互、练习与复习沉淀画像事实；系统据此更新推断、安排迁移练习，并在条件满足时推荐适度进阶内容。

2026-11-14 用户新增激励要求由 Claude 的 [PRODUCT-002](collaboration/PRODUCT-002.md) 定稿：知识卡经 U1～U5 检验解锁；树按知识卡、间隔复习和合理关联成长；小组每周成长增量排行；练习难度随实际表现调整。所有数值都是起点、待数据校准；B 阶段正在逐项实现，状态以本节后面的验收记录为准。

两类卡片必须区分：**错题卡**来自一道题，保存学生作答、卡点和探索材料；**知识卡**经某个知识点的 U1～U5 检验解锁，引用错题卡，允许孩子写自己的话、改标题并拖入知识树。诊断中的 card 字段仍是一段知识讲解；错题卡与检验解锁的知识卡是另行保存的独立对象。

本阶段不包含其他学科、奥数、整卷自动批改、班级管理或第三方日历集成。2026-11-15用户新增FR-035官网/会员及收款待接入流程，Lumi长期会员赠品组合进入测算，真实支付与硬件履约单独验收；不替代网页学习主流程。

## 4. 用户流程与状态

```text
拍题 / 图片 / 当前PDF页 → 点击识别并整理 → 整图分题与角色归属 → 清晰题自动接收，异常题独立待处理
  → AI 整理错题卡（原样作答、卡点、知识关联、探索材料）
  → Agent 在合适时间产出复习待办 → 客户端主动提醒
  → 孩子回忆、探索、适度挑战 → 答对检验 / 迁移题 → 获得对应知识卡
  → 孩子拖动 / 键盘编排知识卡 → 保存自己的知识树
  → 树成长与同组排行带来成就反馈 → 补笔记、整理关系、继续复习
  → 复习与交互沉淀画像事实 → 更新带依据的推断与偏好
  → 个性化巩固 / 迁移 / 条件满足后的进阶 → 新一轮错题与复习
```

必须区分：未选文件、准备预览、可识别、识别中、逐题待处理、生成中、可学习、失败可重试。诊断必须区分：尚未作答、已核验正确、已核验错误、变形等价但未完成、无法核验 / AI 分析待核对。识别或解析失败不是学生做错。

新闭环的五项最低条件与当前差距：

| 条件 | 目标 | 当前状态 |
|---|---|---|
| C1 | 整图识别后清晰题自动整理成学习记录/经核验的错题卡 | 独立卡片对象、笔记、去重已通过Astra G2与网页G6复验（本机合成输入） |
| C2 | 到期时带具体任务主动提醒，孩子无需先发起提问 | macOS 客户端已完成假服务及真实复习服务联调；可见通知与 G3 待完成 |
| C3 | 复习后答对对应知识点的检验 / 迁移题，解锁知识卡 | 检验、U1～U5、重复解锁与低分停止已通过Astra G4/G6复验 |
| C4 | 孩子亲手把知识卡放入树，位置与层级可恢复 | 持久布局、指针拖拽、键盘/菜单移动、撤销及版本冲突已通过Astra G5/G6复验 |

## 5. 功能需求与验收标准

### FR-001 · 拍照与文件上传（P0）

按用户最新要求与 [ASTRA-DESIGN-003](collaboration/ASTRA-DESIGN-003.md)，默认拍照/上传后点击“识别并整理”，当前整图最多12道大题自动分题，不要求先框选和逐题校准。子问共用题干/图表；超限明确还有未处理内容。框选/原图查看只是可选恢复。PDF仅处理当前页。

- 学生录题只保留“拍照录题”和“上传图片 / PDF”两个入口；首屏不出现独立手动录题、示例题或空白公式输入框。
- 图片不超过 10 MB；PDF 不超过 20 MB、最多 100 页。PDF 可换页，图片与 PDF 页图可框选一道题，支持键盘调整选框。
- 选择或换页不触发模型。图片先本机预览；PDF 上传给应用服务，在内存中渲染选定页，不保存原文件。
- 点击识别才将选定页图或选区发给模型，不把原始 PDF 发给模型。损坏、加密、不支持格式、超限和取消选择均有明确恢复方式。

### FR-002 · 多题识别、归属与自动接收（P0）

- 原样保留学生错误，不将模型纠正后的步骤冒充学生作答。题干、作答、图形条件和疑似模糊位置可供核对；识别后的编辑仅用于校正。
- 教师批注、红笔记号和邻题笔迹不得混入学生步骤，也不直接当作判题事实。识别模糊字符时，先用题干印刷内容和学生同题其他书写作上下文推断；不使用标准答案、程序判对错或“数学上应该是什么”来改写真实错误。人工参考读法同样需要对照原图复核。
- 模糊位置保留2–3个候选及依据，只有学生自身上下文唯一支持时可采用并标推断。旧单题兼容API保留一键选候选机制；本批默认多题界面仅重拍/可选框选，不开放手工覆盖版本。仍不明确只跳过该题，其余继续，不要求校准整页。
- 被划掉内容与重写内容区分；划掉内容不进入作答，不能确定是否划掉则保留歧义。推断不能补造学生没有写的完整结论。若有双模型结果，分歧是消歧线索，不用多数票代替证据；当前单一指定国产视觉模型 `kimi-k3.1-pro`（独立验收后发布），不默认增加第二次付费调用。
- 上述上下文消歧是 Claude 的 P0 设计决定 [DESIGN-001](collaboration/DESIGN-001.md)，目前待实现 / 专项验收；不能因本段写入就宣称已经修复。
- 整图识别多道独立题，模型按阅读顺序区分题干、学生作答、教师批注、划掉内容及未知片段；作答可以写在题干内、旁边或上方，角色不由矩形位置或印刷/手写单独决定。无法归属的片段单独保留，不复制到每题。完整、无关键疑点且作答归属明确的题由服务端自动接收；缺条件/缺图/未知作答或关键歧义仅该题待处理，不要求校准整页。
- 未有有效服务端来源与明确接收状态不诊断；自动接收是识别流程决定，不是数学正确证明。无法程序核验的推理只作待核验学习记录，不增加错因/错误次数、掌握或解锁。批次/题目/版本幂等，重试不重复建卡。换文件/页/选区或取消会停止未开始任务，迟到响应不覆盖新页。

### FR-003 · 有作答的步骤诊断（P0）

- 在可核验范围内定位第一个错误，并将后续未检查步骤与正确步骤区分显示。因式分解须分解彻底；分式须化到最简并保留原式定义域。
- 原题照抄或未完成的等价式不能算做完；引入额外分母限制的变形不能因代数值相同而通过。
- 错因指向具体规则和知识点，不给孩子贴“笨”“粗心”等标签。程序无法解析时保留原输入，不能强行判错。
- 当前代数接口有界：题干 / 每步最多 120 字符、最多 12 步；扩展题型不可未经适配直接塞进该接口。

### FR-004 · 只有题干的新题学习（P0）

- 无作答进入“尚未作答”；可看提示、图形、知识卡和追问，不补造作答或卡点，不增加错题次数、错因及掌握记录。
- 只有后续真实练习结果才能增加相应练习进度、初次点亮并创建复习。原题学习记录与错题记录应可区分。

### FR-005 · 三级提示和知识卡（P0）

- 提示按 1 → 2 → 3 逐级解锁：方向、关键步骤、完整解法。前两级及其 AI 追问不自动泄露完整答案。

- 与课标位置不同只作建议，不强制改回；家长只读。参考目录与孩子的可编辑树分别呈现；只读参考目录本身不代替孩子整理。

### FR-023 · 持续学习者画像（P0）

验收引用：PRODUCT-001 的 PROD-A3、PROD-A4。

- 三层分别返回与展示：事实 facts（练习 / 错因 / 复习记录）、推断 inferences（带 based_on 事实引用与置信说明）、偏好与目标 preferences（孩子 / 家长提供，可改）。
- 推断能追溯依据，孩子可反驳并记录反驳、降低该推断可信程度。使用具体学习描述，不贴能力或人格标签；主观“懂了”不直接改变掌握状态。
- 掌握状态仅 not_started（未接触）、consolidating（在巩固）、stable（较稳定）。初次点亮与 stable 分开。
- Claude 提议的 stable 起点为同一知识点间隔至少 3 天、两次独立做对且最近一次无提示；这是待教师 / 家长和真实数据校准的起点。AI 越来越了解孩子体现在可追溯画像和推荐变化，不宣称模型自动训练。

### FR-024 · 迁移与适度进阶推荐（P1）

验收引用：PRODUCT-001 的 PROD-A2、PROD-A7；新闭环的推荐反馈还须满足 C5。

- 基于画像事实和掌握证据安排巩固、同知识点变式、前置 / 相邻知识点迁移。每项有 reason 与 based_on 事实引用，完成情况反馈给下一次推荐。
- 进阶仅在前置知识点 stable、有稳定证据引用、后继尚未接触且前置关系明确时推荐；缺证据不推超前内容。
- 推荐练习须能独立核验；无法核验的探索内容标 ai_review。Claude 的初始节奏为每周最多一个进阶知识点，可拒绝并记为偏好，不短期重复；该节奏仍待验证。
- AI 自身的改进通过反馈、提示版本、独立评测与 Astra 审查控制，不能把“共同迭代”解释成自动改评分、代码或发布。

### FR-025 · 树成长与多用户排行榜（P1）

依据：PRODUCT-002 第 5 节，验收 INC-A5～A10。下列计分、次数与上限均为起点，待教师 / 家长意见和真实数据。

- 成长分 = 规模 S + 茂盛度 L + 关联 R。S：每个首次解锁的知识点 +10；L：同一知识点间隔至少 3 天、答对且 verified 的有效复习每次 +3，每点最多计 3 次；R：符合课标前置关系的合理连线每条 +2，最多计 20 条。
- 评估知识关系，不评估像素位置。孩子自由摆放、自建分组；新建连线须填写自己的理由。目录未收录的联系保留为“孩子自己的联系”，进入复核，不计分也不判错；与目录相反只提示一次、不计分。模型可评论孩子的理由，评论不参与计分。
- 目录依据需可追溯。当前 37 节点 / 31 个前置关系来自项目常见主题大纲，尚未完成教材 / 官方课标核对，不能表述为已获官方核验；真实计分前需按教材映射复核，关系规则使用可追溯的目录版本。
- 榜单限监护人创建并授权的小组，以每周成长分增量排序，可看累计成长；展示昵称、成长分及三部分明细、树缩略图，不能展示真名、学校、错题、错因或画像推断。孩子 / 监护人可退出，不再显示。
- 排行不能简单按上传错题张数、点击次数或重复作答计分。知识卡来源、检验证据、重复授卡与重复计分须可追溯。
- 成长与布局分离：规模按知识点首次解锁、关联按有方向的知识点对首次合格事件去重，不以卡片 / 连线编号去重。移除卡片、删线或撤销不减少历史成长，重新放回或重建同一关系也不重复得分；茂盛度按知识点与间隔复习事件去重。
- 不比速度，不因答错扣分，不让树枯萎、掉叶或使成长分衰减，不使用连续打卡倍数，也不以掉名次催促孩子。成长分算术由服务端校验；Schema 不负责把三部分相加。
- 当前是匿名本机演示，没有真实多用户与隔离授权；此处是目标需求。真实排行榜上线依赖 FR-018 的账户、授权与数据隔离验收。

### FR-026 · 适度挑战与难度调整（P0）

依据：PRODUCT-002 第 4 节，验收 INC-A8。以下目标区间和调整规则均为起点、待数据，不是已证实的学习效果。

- Agent 结合当前知识点、前置基础、实际答题与提示使用，选择合适的巩固、检验或迁移练习，并说明下一题的目的。
- 暂以 60%～80% 的题能答对为设计目标；一组三题全对且无提示，下一组升一档或推荐相邻知识点；答对 2 题保持；答对至多 1 题则降一档并给例题 / 支架；连续两组至多答对 1 题，停止出新题、返回知识讲解。进阶仍受 FR-024 的 stable 条件约束。
- 依 Astra 的 [DEC-004](collaboration/decisions.md)，连续两组低分后暂停该档案/知识点当天的新检验，主动作回到讲解；北京时间次日清暂停与低分连续计数。刷新、换 request_id 不绕过；已有组可查看/继续作答但不清暂停，其他知识点不受影响；旧状态按最近完成时间迁移。本条修复已由Astra独立复验通过，不锁定学习资料。
- 难度档位来自步骤数、分式、参数等程序标注属性，不由模型随口评分。不设倒计时、不比较速度；孩子随时可停，已有学习成果保留。
- 孩子能表达太简单、太难或想休息；答题表现改变下一步安排，不能持续机械重复同难度题或无限加题。
- 只有可核验的正确作答可以用于知识卡解锁；难度调整、孩子主观感受和模型推断分别记录，不能将感受当作掌握事实。

### FR-027 · 激励与持续投入闭环（P1）

依据：用户的 Hooked 映射与 PRODUCT-002 第 2 / 6 节；验收 INC-A7～A10。

- 触发：从学校错题与首次拍题开始，后续由具体复习待办承接；行动：完成适度挑战的复习 / 练习；酬赏：答对后获得知识卡、看到树成长与排行；投入：持续拍题复习，并积累孩子自己的笔记、知识关系与学习偏好，改善下一轮体验。
- 本阶段不做随机酬赏。后续如探索，只考虑叶片外观等装饰变化，不影响知识卡、成长分、排行或学习内容；不能随机决定孩子是否获得已经达标的知识卡。
- 投入应改变下一次体验，例如推荐理由引用孩子笔记中记录的卡点；这是目标能力，实现前不能宣称已根据笔记推荐。
- 每轮有可结束的小目标。衡量应包含延迟复习表现、知识卡与整理完成情况，不能只用停留时间或拍题数量判断产品成功。
- 框架来源：[Nir Eyal 官方 Hooked 资料](https://www.nirandfar.com/hooked-user-behavior-resources/)。此处是本产品的设计映射，不代表已证明对儿童学习有效。

## 7. 数据与接口协作契约

核心对象：邮箱账号、服务端绑定学习档案（本机仍可匿名演示）、题目 / 识别结果、诊断或学习上下文、知识点、练习及组、复习、可用时间、反馈。题目与练习的判断依据由服务端保存；同一档案的学习桌、树、计划使用同一结果；家长页只访问同基础账号且已通过独立家长密码的档案；数据对象新增parent_password（盐/慢哈希/版本）、parent_code（账号/用途/期限/消费）、parent_session（基础session摘要/密码版本/15分钟期限）；旧关系仅留历史、不授权。FR-033摘要接口不接受学生选择参数。状态含义见第 4 节。

| 链路 | 现有接口 | 变更要求 |
|---|---|---|
| PDF 预览 / 识别 | `/api/files/preview`、`/api/recognize` | 预览不调用模型；网页走`/api/recognize/page`与`/api/study/reading`服务端自动接收，旧`/api/recognize`保持单题兼容 |

## 9. Codex / Astra 协作与变更流程

- **DEV-001 · 共同基线与决策权：** 两方先读本文、根目录 `AGENTS.md` 和协作协议；Astra 通过 `ASTRA.md` 进入同一规则。用户明确指令最高优先；Astra 负责产品方向、设计缺陷判定、优先级与监督验收，Codex 负责实现、测试与修复。方向 / 核心设计变更由 Astra 决定并同步本文和决策记录，Codex 可建议但不自行改变方向。
- **DEV-002 · 认领与通信：** 编辑前通过 `tools/coord.py` 认领具体文件或目录；不同代理不能认领重叠路径。通过共享消息传递接口提案、依赖、风险和交接；不共享密钥、原始儿童资料或私有聊天全文。
- **DEV-003 · 下发、执行与监督：** Astra 将设计缺陷、理由、目标、优先级、修改边界和验收条件交给 Codex；Codex 认领执行、自测并回传需求编号、文件、结果和限制，再释放认领。Astra 依据证据验收或提出具体返工项；Codex 自测通过不能代替 Astra 验收。用户直接指定的要求与既定范围内常规修复可继续执行，不增加重复的人类审批。

流程：Astra 审查并确定方向 / 缺陷任务，或用户直接下达明确要求 → 关联需求并检查消息 / 认领 → 必要时同步 Astra 的决定、PRD 与接口 → Codex 实现、自测和修复 → 回传文档与证据 → Astra 验收或下发返工。普通修复可在既有需求内直接执行；涉及另一方占用的文件时先协调，独立工作继续。
